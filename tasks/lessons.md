# Lessons

- Production fork scope is allowed to diverge from the open-source SearchTube defaults. Do not spend effort preserving local/no-auth UX unless it directly helps hosted development or testing.
- For Ghost Peony design work, the design system lives at `C:\Users\Cade\.claude\DESIGN_SYSTEM.md`, not the Codex path. Read that before UI work and apply Botanical Brutalism: warm botanical palette, serif brand type, monospace labels, honest borders, offset shadows, and press-in interactions.
- Do not put a nav item on a product landing page that links to the same product domain. Use meaningful on-page anchors or actions instead.
- Memexai landing-page art should be minimal and architectural, not busy faux-product art. Aim for famous-modern-minimalist restraint paired with golden-era brutalist architecture: negative space, one strong form, quiet film/transcript references, and no cheesy demo-card illustration.
- Do not use decorative section badges as a default pattern. Remove boxed eyebrow labels like "Hosted transcript search," "Workflow," and "Use cases" unless they carry functional state or navigation meaning.
- The landing-page chunking visual should be simplified and striking, closer to a Japanese anime production frame than an explanatory graph. Avoid dense bead fields, fake UI diagrams, and abstract copy like "searchable matter."
- When replacing a disliked visual, remove the old wrapper styles too. New markup nested inside stale diagram CSS can make the rendered page look unchanged even when the component changed.
- For premium landing imagery on Memexai, prefer generated bitmap art over CSS/SVG-like constructed diagrams when the user asks for a polished product-art feel.
- Do not over-explain product features or auth mechanics in visible UI copy. For Memexai beta auth, prefer a confident Google-only sign-in surface over magic-link fallback unless usage shows a real need.
- HARD RULE (DESIGN_SYSTEM.md lines 24, 82): never add boxed eyebrow/badge/pill tags for section names, taglines, or feature labels (e.g. a "Second brain for video" tag above the hero H1). Badges are functional-state only. Use prose/hierarchy. Read DESIGN_SYSTEM.md BEFORE touching any landing markup.
- Never fabricate a "live demo" mockup of the product UI on the landing page. A made-up query/answer/result card that does not match the real dashboard is worse than no demo. Use a real screenshot/GIF of the actual app, or leave the existing art.
- Keep Memexai positioned as universal video knowledge, not an AI/ML-only tool. AI/ML research is a strong motivating use case, but taxonomy, retrieval evals, docs, and product copy should work for any YouTube topic a person saves.
- When hosted migration appears blocked by model quota or profile/auth friction, first look for reusable local artifacts and idempotent repair paths. In this project, reusing local Chroma vectors let the 30-video corpus migrate without new Gemini embedding spend.
- The product name/domain decision is Memexai at `memexai.xyz`. Public UI, docs, metadata, agent setup snippets, and generated assets should use Memexai; legacy `SEARCHTUBE_*` env vars and the linked `embedmoments` Supabase project id can remain internal compatibility details until a deliberate migration is planned.
- Connect YouTube is not just a Settings utility. Treat it as first-time user setup: after first Google login, guide users through YouTube read access, a dedicated save playlist, and an MCP token so the human and their agent can start with very few clicks.
- FTUE should drive activation, not education alone. A new user should leave onboarding with a connected source, a first queued/searchable video, and a clear agent setup path instead of only learning where Settings lives.
- For agent-first onboarding, OAuth-native MCP is the main product path and dashboard-created MCP tokens are the fallback. The agent client should be able to discover Memexai, open auth, get approval, and call `get_mcp_session` without the user visiting Settings first.
- Keep Memexai product-story copy on the public landing page. The authenticated dashboard should be an input-first workspace for adding/searching video context, with usage and operational surfaces around the edges. Do not put large explanatory hero/header containers above the URL/search input.
- If a user says screenshots do not reflect requested UI changes, inspect the rendered hierarchy for stale panels and wrapper styles before continuing. A passing build is not proof that the visible product surface changed.
- Production customer UI should not expose local-dev language, localhost endpoints, raw `llms.txt`/manifest links, or long agent-internal explanations. Keep authenticated surfaces operational; hide agent setup mechanics behind concise copy actions or dedicated setup flows.
- Do not frame Memexai as a thin YouTube transcript index. The core wedge is: YouTube is a major learning surface, users already curate useful videos by saving them, and Memexai turns those chosen videos into reusable memory/source-graph context so agents do not start from blind web search or repeated pasted-link ingestion.
- Keep Settings compact and operational. Avoid extra explanatory lines like “connect once...” or hosted/model-access reassurance blocks unless they directly prevent user error; show status, controls, and copy actions instead.
- If Library has indexed videos but the Video Breakdown is empty, do not present it as an empty library. Check backend grant compatibility (`user_channels`, `user_videos`, legacy `videos.indexed_by`) and API fallback behavior, then show a catching-up state if graph rows are not available yet.
- YouTube watch URLs often include playlist context (`watch?v=...&list=...`). For dashboard URL ingestion, treat those as single-video imports; only explicit playlist URLs like `/playlist?list=...` should run playlist ingestion.
- Cloudflare Container env propagation is tied to the Durable Object/container instance lifecycle. In `workers/api/src/index.ts`, build container `envVars` from `this.env` inside the Container class and route new runtime changes to a fresh stable instance when secrets/config need to be picked up.
- If a single-video import fails before transcript/chunk progress starts, persist at least one failed-video counter and keep the recent failed job visible in Library. An empty video library should not hide the user's latest import failure.
- Library removal must be user-scoped by default. In the shared canonical video model, a user action should revoke/hide that user's access grant; deleting global video/chunk/source-knowledge rows belongs in a separate orphaned-source garbage collector.
- Keep enum-like database constraint values mirrored in backend validation and tests. Supabase fakes will not catch invalid text values such as unsupported `user_videos.access_source` strings unless the code validates them before insert.
- YouTube ingestion must treat timestamp and share parameters as playback context, not source identity. Parser tests should cover watch URLs with `t`/`start`, `youtu.be`, mobile/no-scheme links, Shorts, Live, embed/v paths, playlist-context watch URLs, and channel handle/path variants.
- Do not let frontend Library fetch failures return an empty library. Empty means the user has no saved videos; backend/API failure needs a visible retry state so successful imports do not look lost.
- Treat legacy schema columns such as `videos.indexed_by` as optional in production code. The hosted Supabase schema can differ from old migrations, so source graph/library paths need guarded fallbacks for historical compatibility.
- Video Breakdown UI should be video-first for customers. Do not lead with node types, labels, edges, QA/static diagnostic notes, source-map metaphors, or backend retrieval modes.
- Timestamp source links should read like human actions (`Open at 5:02`), not implementation labels (`videoId @ 5:02`) even when the href still contains the YouTube ID.
- Library generated knowledge should feel like readable saved-video artifacts, not a diagnostics inspector. Keep videos and extracted knowledge together, remove redundant counts, and open long guides/summaries in an in-app modal while timestamp links use the idea/moment text itself.
- Do not present raw transcript chunks as a primary Library feature. Mid-sentence text clips without surrounding context feel broken; use them only as source evidence behind guides/key ideas unless the backend can provide coherent highlights with enough context.
- Never build the human Library reading surface from compact graph excerpts when full artifact content exists. Preserve `knowledge_artifacts.content` for guide modals/views, and reserve truncation for explicit MCP/search response budgets.
- Memexai video digestion should emulate gbrain's curated entity-page pattern, not plain summaries: Compiled Truth, Agent Quick Index, people/orgs/tools, claims, decisions, timeline, and source-backed evidence first; raw transcript access is the fallback for verification.
- When demonstrating or testing Memexai guide quality, never use sparse placeholder examples or ellipsized snippets as the quality bar. Examples should show dense, specific, timestamp-backed source-page content so the expected output feels materially different from a summary outline.
- Keep Memexai's default analysis contract uniform for every indexed video. Scale report length and item counts by transcript duration/substance, not by whether the video came from a single URL, playlist, channel, starred source, or agent submission; `basic`/`none` are explicit cost-saving modes.
- Do not present local/sidecar runtime as a customer offering yet. Treat local mode as dev/internal roadmap context only; paid-tier planning should focus on hosted Supabase/Cloudflare subscriptions.
- Keep Memexai paid pricing individual until there is signal validation for shared/team workflows. Do not add Team/seat pricing, SSO, or pooled team libraries to v1 Stripe plans by default.
- Customer-facing video artifacts should be framed as TLDRs and source reports, not study guides. Report content must render markdown-like structure and source timestamps as usable links; topic cards without timestamp evidence should not occupy the primary Library surface.
- Mobile QA for the authenticated dashboard must use realistic populated data, not only empty/error states. Long job URLs, channel names, and capture-source titles can expand CSS grid min-content width unless dashboard cards, grid children, and row containers explicitly use `min-w-0`/overflow constraints.
- Playlist capture sync should not silently queue one item when multiple playlist videos are pending. Use a preview sync to count all queue candidates, ask the user to confirm the count, then queue the confirmed number.
- If full repo lint fails on eval or tooling files after a production patch, fix the lint unless there is a concrete reason not to. Eval harnesses are part of product quality for Memexai, even when they are not imported by the production runtime.
- Customer-facing confirmation flows should use app-rendered modals, not `window.confirm`, so the copy, count, and next-step status can match the product UI.
- Queue-all playlist sync should not mean concurrent embedding. Queue all confirmed items for user visibility, dispatch one background job, and let the hosted worker drain the rest sequentially with rate-limit backoff.
- Capture-source items must be reconciled from their ingestion jobs after success, failure, and retry. A playlist row left in `queued` after the job completed or failed makes the pipeline look stuck even when the job history is correct.
- Library search should behave like the dashboard search unless a scoped search mode is explicitly labeled. Do not hardcode a different result limit or keep users in an inline mini-results surface when the dashboard uses the full answer/player/citation workflow.
- Cloudflare can return Error 1010 before the Memexai Worker when an MCP client uses a bare/default Python HTTP signature. Production MCP evals should send a normal User-Agent such as `ModelContextProtocol/2025-06-18`, and the product needs a Cloudflare allow/skip rule for `/mcp` if we want arbitrary agent HTTP clients to work without custom headers.
- Cloudflare Container deploys can leave the warm Durable Object container serving the old image when the instance name is pinned to `production`. Bump or version the container instance id after backend deploys, or automate instance-id/version rotation, before trusting production evals.
- MCP tool responses should not duplicate large JSON payloads in both `content[].text` and `structuredContent`. Keep full machine-readable data in `structuredContent` and summarize large text content so agent token usage remains better than pasting transcripts.
- Library topics and reports must be structured for browsing, not dumped as long extraction feeds. Group topics by human categories, show the source video on every topic, dedupe repeated same-timestamp ideas, and keep TLDR/source reports organized per video rather than repeated in an endless scroll.
